Distributed inference / Personal lab

When a healthy cluster is still slow

EnvironmentTwo-box DGX Spark / GB10

FocusPrefill throughput

MeasurementPublished reference comparison

The problem

The original portfolio reports that the link between two machines ran at a fraction of its expected speed while diagnostics appeared healthy. A connected cluster was not sufficient evidence that distributed inference was performing as intended.

Engineering focus

The work centres on validating the actual communication path and model workload: RDMA, both ConnectX rails, NCCL configuration and prompts representative of the client. The deliverable for this type of engagement is a working configuration, benchmark results and an operating runbook.

Reported result

The existing portfolio reports Qwen prefill at 104–111% and GLM prefill at 103–116% of published reference figures for the same two-box setup. These figures describe prompt processing; they do not establish faster token generation, better answer quality or a business outcome.

Evidence and limits

These figures are carried forward from the original portfolio. This public case study does not yet include the model revisions, reference links, prompt lengths, engine versions or raw benchmark logs needed to independently reproduce the comparison. Treat it as a reported lab result, rather than an independently verified performance guarantee.

Why it matters

For a team deploying large models, checking actual workload performance can reveal bottlenecks that connection and health checks miss. Acceptance should depend on the intended application, alongside measured throughput.

Source: measurements described in the original eAccelerate portfolio. This is personal lab work; no client engagement or testimonial is implied.
